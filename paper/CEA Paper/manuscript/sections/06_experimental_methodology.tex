\section{Experimental Methodology}
\label{sec:experimental_methodology}

\subsection{Experimental Principles}
All evaluations follow five fixed controls.
\textbf{(C1) Frozen partitions:} each test set is frozen on disk before any tuning; thresholds and prompt strategies are selected on development splits only and never on test.
\textbf{(C2) Identical inputs across systems:} every baseline receives the same raw query, image, and context.
\textbf{(C3) Deterministic seeds:} seeded runs use seed 20260827 (or 20260813 in the first-tier layers); the exact seed per layer is recorded in the experiment registry.
\textbf{(C4) Pre-registered metrics:} endpoints are the CUAR, CAC, coverage, and appropriate-abstention definitions of Section~\ref{sec:problem_formulation}, plus per-layer auxiliary metrics.
\textbf{(C5) Statistical protocol:} binary proportions use 95\% Wilson intervals; paired comparisons use McNemar's test with Holm--Bonferroni correction across the baseline ladder; latency is reported as p50/p95/p99 when a distribution exists; risk--coverage uses AURC and fixed-risk coverage.

\subsection{Benchmark Suites}
The battery spans nine evaluation corpora, comprising approximately 60,000 evaluation cases across 36 completed layers:
\begin{enumerate}
    \item \textbf{Adversarial misbinding suite} (10,000 cases): 10 corruption families $\times$ 1{,}000 cases each, juxtaposing valid facts across records (Layer E02).
    \item \textbf{11-slot hazard suite} (13 configurations $\times$ 10{,}000 cases): single-slot ablation isolating safety per contract field (Layer E03).
    \item \textbf{Counterfactual binding suite} (2,000 pairs): true vs.\ mutated evidence certification (Layer E05).
    \item \textbf{Multi-register benchmark} (4,000 cases): Standard Bengali, farmer queries, dialects, and Banglish, 1{,}000 each (Layers E06, E17, E21).
    \item \textbf{Risk--coverage corpus} (20{,}112 cases): 12{,}068 train / 4{,}022 dev / 4{,}022 test; threshold frozen on dev (Layer E04).
    \item \textbf{Adversarial security suite} (1{,}400 cases): seven attack families including native and Banglish injections (Layers E07/E08, E22).
    \item \textbf{Temporal conflict suite} (100 cases/system): obsolete-vs-current gazette and source conflict tests (Layer E30).
    \item \textbf{Cross-modal conflict suite} (100 cases/system): text crop identity vs.\ visual classification (Layer E31).
    \item \textbf{Rural network suite} (1{,}000 queries $\times$ 4 profiles): 4G/3G/Edge/2G latency, loss, and jitter profiles (Layer E14).
\end{enumerate}

\subsection{Baseline Ladder and Fairness Controls}
Because the underlying failure modes differ per layer, we define a canonical baseline ladder and instantiate the relevant subset in each layer. All systems share the same frozen inputs within a layer (C2). Baselines were configured using standard published industry best-practices---standard LangChain/LlamaIndex BM25+dense RAG with official hyperparameters; standard zero-shot and few-shot evaluation prompts for LLM-as-a-judge. The LLM judge baseline was evaluated under standard off-the-shelf single-turn verification prompts and was not specifically prompt-engineered with multi-step temporal scratchpads, reflecting standard production guardrail deployments rather than an optimized upper bound.
\begin{itemize}
    \item \textbf{B0 --- Unconstrained LLM.} Direct generation (GPT-4o-Mini in live-API layers).
    \item \textbf{B1 --- Vanilla RAG.} BM25/lexical retrieval feeding the generator without authority constraints (Llama-3.1-8B in live layers).
    \item \textbf{B2 --- Guarded RAG.} Input risk-classifier before retrieval.
    \item \textbf{B3 --- RAG + post-hoc LLM judge.} A secondary LLM evaluates textual faithfulness of the generated answer.
    \item \textbf{B4 --- Deterministic structured resolver.} Fact traversal with no generation.
    \item \textbf{B5 --- Evidence-constrained RAG.} Multi-document citation with a partial slot matcher but \emph{without} single-record joint binding (the isolation baseline for the contribution).
    \item \textbf{B6 --- BAA (this work).} The full bounded-authority architecture.
\end{itemize}

\subsection{Expert Evaluation Protocol}
For the agronomist study (Layer E13), three certified agricultural extension specialists rated 200 advisory outputs (50 per system) on correctness (1--5 Likert), chemical safety pass, evidence traceability, and deployment approval. Outputs were presented without system labels in a blinded, randomized order; raters assigned system IDs only post-hoc. Agreement is reported with Gwet's AC1 first-order agreement coefficient \citep{gwet2021}; the primary coefficient on the safety dimension is 0.862, with 0.814 on deployment approval and 0.785 on the correctness scale.

\subsection{Reproducibility Protocol}
Every layer records: script path, spec path, frozen seed, environment (OS, Python, packages), raw-output path, and where applicable the git commit of the code at run time. Layers E02--E26 carry a full verification block (self-checks, determinism re-run on 10\% of cases, trace check, real-application check); the newer live-API layers (E27--E39) do not yet carry that block, and we state this explicitly in Section~\ref{sec:limitations} rather than implying a uniform audit trail.
