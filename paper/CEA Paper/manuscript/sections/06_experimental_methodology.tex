\section{Experimental Methodology}
\label{sec:experimental_methodology}

\subsection{Experimental Principles}
All evaluations follow five fixed controls.
\textbf{(C1) Frozen partitions:} each test set is frozen on disk before any tuning; thresholds and prompt strategies are selected on development splits only and never on test.
\textbf{(C2) Identical inputs across systems:} every baseline receives the same raw query, image, and context.
\textbf{(C3) Deterministic seeds:} seeded runs use seed 20260827 (or 20260813 in the first-tier layers); the exact seed per layer is recorded in the experiment registry.
\textbf{(C4) Pre-registered metrics:} endpoints are the CUAR, CAC, coverage, and appropriate-abstention definitions of Section~\ref{sec:problem_formulation}, plus per-layer auxiliary metrics.
\textbf{(C5) Statistical protocol:} binary proportions use 95\% Wilson intervals; paired comparisons use McNemar's test with Holm--Bonferroni correction across the baseline ladder; latency is reported as p50/p95/p99 when a distribution exists; risk--coverage uses AURC and fixed-risk coverage.

\subsection{Benchmark Suites}
The battery spans eight evaluation corpora, comprising over 140{,}000 evaluated cases and systematic perturbations across 36 completed layers:
\begin{enumerate}
    \item \textbf{Adversarial misbinding suite} (10,000 cases): 10 corruption families $\times$ 1{,}000 cases each, juxtaposing valid facts across records (Layer E02).
    \item \textbf{Counterfactual binding suite} (2,000 pairs): true vs.\ mutated evidence certification (Layer E05).
    \item \textbf{Multi-register benchmark} (4,000 cases): Standard Bengali, farmer queries, dialects, and Banglish, 1{,}000 each (Layers E06, E17, E21).
    \item \textbf{Risk--coverage corpus} (20{,}112 cases): 12{,}068 train / 4{,}022 dev / 4{,}022 test; threshold frozen on dev (Layers E04, E45).
    \item \textbf{Adversarial security suite} (1{,}400 cases): seven attack families including native and Banglish injections (Layers E07/E08, E22).
    \item \textbf{Temporal conflict suite} (100 cases/system): obsolete-vs-current gazette and source conflict tests (Layers E30, E48).
    \item \textbf{Cross-modal conflict suite} (100 cases/system): text crop identity vs.\ visual classification (Layer E31).
    \item \textbf{Rural network suite} (1{,}000 queries $\times$ 4 profiles): 4G/3G/Edge/2G latency, loss, and jitter profiles (Layer E14).
\end{enumerate}

\paragraph{Evaluation units and granularity.} To avoid ambiguity across layers, we distinguish four evaluation units throughout the paper: (1)~\emph{Case}: a single query--context tuple evaluated by one or more systems (e.g., 20,112 held-out advisory cases in RQ3); (2)~\emph{Mutation class}: a semantic corruption operator applied to valid records (11 operators in E28); (3)~\emph{Coverage cell}: a specific (mutation class $\times$ base record) combination evaluated exhaustively (440 cells in E28); and (4)~\emph{System-case}: one case evaluated by one system (e.g., in E28, 11{,}000 mutations $\times$ 7 systems = 77{,}000 system-cases). The ``over 140{,}000 evaluated cases and systematic perturbations'' cited throughout this paper refers to the sum of unique real evaluation cases (real API traces, combinatorial mutations, and deterministic computations) across all 36 completed experimental layers; simulation-only layers are labelled as scenarios rather than measurements.

\subsection{Baseline Ladder and Fairness Controls}
Because the underlying failure modes differ per layer, we define a canonical baseline ladder and instantiate the relevant subset in each layer. All systems share the same frozen inputs within a layer (C2). Baselines were configured using standard published industry best-practices---standard LangChain/LlamaIndex BM25+dense RAG with official hyperparameters; standard zero-shot and few-shot evaluation prompts for LLM-as-a-judge. The LLM judge baseline was evaluated under standard off-the-shelf single-turn verification prompts and was not specifically prompt-engineered with multi-step temporal scratchpads, reflecting standard production guardrail deployments rather than an optimized upper bound. We acknowledge that a heavily optimized judge with chain-of-thought temporal reasoning could narrow the gap; our claim is that the architecture provides guarantees that no amount of prompt engineering can replicate.
\begin{itemize}
    \item \textbf{B0 --- Unconstrained LLM.} Direct generation without retrieval (GPT-4o-Mini in live-API layers).
    \item \textbf{B1 --- Lexical BM25 RAG.} Lexical BM25 retrieval feeding the generator without authority constraints (Llama-3.1-8B in live layers).
    \item \textbf{B2 --- Dense Vector RAG.} Dense vector retrieval (FAISS) feeding the generator (Llama-3.1-8B).
    \item \textbf{B3 --- Citation-Grounded RAG.} Multi-document citation alignment (TarAG / Llama-3.1-8B).
    \item \textbf{B4 --- LLM-as-a-Judge Guardrail.} Post-hoc secondary LLM evaluating generation faithfulness (Gemini-2.5-Flash-Lite).
    \item \textbf{B5 --- Evidence-Constrained RAG.} Partial 8-slot contract without single-record joint binding (the ablation baseline for contract completeness).
    \item \textbf{B6 --- Bounded-Authority Advisory (BAA, this work).} The full five-tier resolution ladder with 11-slot single-record fail-closed certification.
\end{itemize}

\subsection{Reproducibility Protocol}
Every layer records: script path, spec path, frozen seed, environment (OS, Python, packages), raw-output path, and where applicable the git commit of the code at run time. Layers E02--E26 carry a full verification block (self-checks, determinism re-run on 10\% of cases, trace check, real-application check); the newer live-API layers (E27--E31) do not yet carry that block, and we state this explicitly in Section~\ref{sec:limitations} rather than implying a uniform audit trail.
